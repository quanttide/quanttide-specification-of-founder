# 治理成本

治理要花代价。一条规则活下去的理由只有一个：它挡下的损失，大于它带来的麻烦。本文定义这两头怎么数，以及什么时候该删。

## 三项成本

**误拦**是好内容被挡下。代价包括判断它是不是误报、改写、重新提交。挡下的次数乘以单次善后时间，就是这一项。

**漏过**是问题进了库才被发现。代价包括发现与修复，并随停留时间放大：同一处错误，进库一周后才发现，比当天发现贵得多。

**维护**是读、改、迁一条规则的时间。规则越多，每条分到的注意力越薄，这一项随规则数量上升。

三项不必同时开始测。先测漏过，它不需要任何新装置，存量重判一遍就有数。写入拦截装上以后再测误拦。维护按季度摊一次，不逐条计时。

## 净收益

```text
治理成本 = 误拦 + 漏过 + 维护
一条规则的净收益 = 它挡下的损失 − (它造成的误拦 + 它的维护)
```

净收益为负，规则就该删。删之前先确认它挡的那类错误还在不在：还在，说明不是规则多余，是执行没到位。

## 形式化规则

- M1 先测漏过：写入拦截装上之前只测这一项，数据从存量重判取得，不提前搭装置。
- M2 一次打回记一行：时间、规则、真问题还是误报、善后耗时。
- M3 维护按季摊一次：记总耗时，除以在用规则数，不逐条计时。
- M4 负收益即删：连续两个季度为负的规则删除；删前抽查它挡的那类错误是否仍出现。
- M5 零命中复核：连续一个季度没有命中的规则，列为删除候选，抽查确认后再删。

## 边界

度量不能变成新的负担。记录要挂在已有动作上——打回、修复、迁移本来就要做，度量只是顺手多写一行。需要专门抽时间维护的度量，它本身就是成本。

三个数都缺的时候不必等：先删最久没有命中的那批规则。删错了会被重新写回来，那也算一次测得的数据。
