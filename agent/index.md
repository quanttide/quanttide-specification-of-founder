# 智能体协作

人与智能体围绕同一个仓库分工：一方执行并交付产物，另一方评审并放行。

## 自然语言描述

协作由 owner 与 reviewer 两方组成。owner 对执行负责，持有仓库；reviewer 对放行负责，维护规则。两方不得合并——合并即自评自签，评审失效。

仓库是两方唯一的交接点。产物提交进仓库封存，提交历史兼作账本：每轮协作留下分支、提交与产物路径，谁开的单、走过哪站、谁放的行，事后都能查到。产物与回传是协作的凭证；对话不留痕，只传指令与问询，留在对话里的结果不算交付。

一轮协作依次经过派单、执行、交付入仓、验收、回流五站。派单载明对象、任务、交付、合格线与验收人，附上仓库、分支等上下文，使 owner 不读对话也能执行。owner 执行后把产物提交进仓库，交回载明分支、提交与产物路径的回传。验收由 reviewer 对照合格线直接做出：执行可以委派，放行不可委派。评审结论转成下一轮派单，或写入规则与档案，一轮才算收尾。

两方的连接方式分直连与转发，分界在判断的依据：依据仓库里的产物原件为直连，依据回传里的转述为转发。转发结构多一个转发方居中传话，派单与回传由它携带；转发方只传话，不承担执行责任，不参与放行。直连最扁平，判断直接落在产物上，代价是人工操作多；转发省人工，但判断建立在转述上，多一层转发多一道失真。

## 形式化规则

```text
产物面：owner ──产物──> 仓库 ──产物──> reviewer
消息面：reviewer ──派单/回传──> owner             （直连）
消息面：reviewer ──派单/回传──> 转发方 ──> owner  （转发）

一轮：派单(R6) → 执行 → 交付入仓(R2) → 验收(R5) → 回流(R7)
```

- R1 责任分离：owner 与 reviewer 必须由不同主体承担，不得合并。
- R2 凭证落仓：每轮交付必须以产物形式进入仓库，可按分支、提交与产物路径追溯；留在对话里的结果不是凭证，不算交付。
- R3 对话限令：对话只传指令与问询，不得承载交付。
- R4 转发方限令：转发方只转传派单与回传，不得代做判断，不得改写传话内容。
- R5 放行归属：执行可以委派，放行不得委派；验收必须由 reviewer 直接做出。
- R6 派单自足：派单必须载明对象、任务、交付、合格线与验收人，附上仓库、分支等执行上下文，使 owner 不读对话也能执行；转发结构下还必须载明失败回传方式。
- R7 回流归档：评审结论必须转成下一轮派单，或写入规则与档案；账本由此连续，事后可查。
