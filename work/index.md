# 工作结构

一方执行并交付产物，另一方评审并放行；一轮工作依次经过派单、执行、交付入仓、验收、回流。

## 自然语言描述

工作由 owner 与 reviewer 两个角色组成。owner 对执行负责，持有仓库；reviewer 对放行负责，维护规则。两个角色不得合并——合并即自评自签，评审失效。

仓库是两个角色唯一的交接点。产物提交进仓库封存，提交历史兼作账本：每轮工作留下分支、提交与产物路径，谁开的单、走过哪站、谁放的行，事后都能查到。产物与回传是工作的凭证；不经仓库的结果不算交付。

一轮工作依次经过派单、执行、交付入仓、验收、回流五站。派单载明对象、任务、交付、合格线与验收人，附上仓库、分支等执行上下文，使执行方无需依赖对话即可执行。owner 执行后把产物提交进仓库，交回载明分支、提交与产物路径的回传。验收由 reviewer 对照合格线直接做出：执行可以委派，放行不可委派。评审结论转成下一轮派单，或写入规则与档案，一轮才算收尾。

两方由智能体承担时，消息按[双智能体协作](../agent/index.md)传递；角色与流程不随之改变。

## 形式化规则

```text
产物面：owner ──产物──> 仓库 ──产物──> reviewer
一轮：派单(R6) → 执行 → 交付入仓(R2) → 验收(R5) → 回流(R7)
```

- R1 责任分离：owner 与 reviewer 必须由不同主体承担，不得合并。
- R2 凭证落仓：每轮交付必须以产物形式进入仓库，可按分支、提交与产物路径追溯。
- R5 放行归属：执行可以委派，放行不得委派；验收必须由 reviewer 直接做出。
- R6 派单自足：派单必须载明对象、任务、交付、合格线与验收人，附上仓库、分支等执行上下文，使执行方无需依赖对话即可执行。
- R7 回流归档：评审结论必须转成下一轮派单，或写入规则与档案；账本由此连续，事后可查。
