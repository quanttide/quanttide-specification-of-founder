# 文档头

文档头指 Markdown 开头两行 `---` 之间的 YAML 块。它不承载正文，只放两类信息：这份文档到了哪一步、由谁写成。

有文档头的按本规格检查，没有的不强制补。字段名不在表里报嫌疑，取值不在表里报错。

## 字段

| 字段 | 取值 | 记什么 |
| :-- | :-- | :-- |
| `status` | `draft`、`pending`、`final` | 到哪一步：还在写、写完待核、已核实可引用 |
| `authors` | 每条带 `type`，取值 `human`、`agent`、`org` | 谁写的：人、模型、法人 |
| `context` | 见文档契约 | 属于哪个领域：正文主题所在的那个领域 |

MyST 的保留字段——`title`、`description`、`exports` 等——归站点渲染，不在本规格管束内，一律放行。

## 形式化规则

- D1 字段先入表：新增字段先写进契约，再出现在文档里。
- D2 状态三档：只认 `draft`、`pending`、`final`；不确定的用 `pending`，不另造近义词。
- D3 署名留痕：每条 `authors` 标 `type`；`agent` 写模型名，`org` 写全名。
- D4 语境声明：`context` 声明文档所属领域，语言检查据此放行该领域的词；未声明的按跨语境处理。

## 边界

文档头只管元信息，不判正文好坏。状态标 `final` 不等于内容已核实，核实另由人判。

语境声明说明的是文档主题，不是豁免通道：声明了财务，只放行财务领域的词，别的领域照报。
